Copilot CLI protocol (runs 21 onwards, `round.ps1 run`): the CLI footer (`AI Credits`, `Tokens`, `Changes`) is **cumulative for the session**, so a resumed verify stage is read as session total minus the task turn (`-ResumeCumulative`). Resuming re-sends the whole context (a one-word reply on a resumed T3 session cost ~12 credits with 477K tokens uploaded, 87K of them uncached), so "verify afterwards" in arm A includes the price of reloading the context, which is exactly what a developer pays when guardrails are added after the fact. CLI token totals (170-220K) count every request of the session and are not comparable with the VS Code "Session Info" numbers (33-64K); compare CLI runs only with CLI runs (`analyze.py --model-contains "Copilot CLI"`). CLI runs also have no files.exclude, so arm B in the CLI is "instructions + policy" only.

Session tokens include roughly 34K of fixed Copilot overhead (system instructions + tool definitions, 3-4% of the 1M window). The repository-dependent share is the difference above that floor.

Local Karma "ChromeHeadless has not captured" (2026-09-24): VS Code auto-forwards the Codespace's Karma port 9876 to localhost after a test run in the Codespace, so local Chrome connects to the forwarded port instead of the local Karma server. Fix: Ports panel in the Codespace window, Stop Forwarding Port 9876. This is also what made the arm B agent report "no Chrome binary" in run 16.
